# Team Hub M4 preparation tools

Current authority: [final stateful preparation gate](../../docs/architecture/team-hub-2b3-dark-target-readiness.md). Prefer empty-source Mode A, two dark tables, no migration writer identity, no logo bucket. All live tools are read-only; no AWS write/deploy adapter is supplied.

Final offline tools: `native-state.mjs` implements closed `team-hub-state.v1` native-new-record reversal and the empty gate; `prepare-final.mjs` and `prepare-write-proposals.mjs` render local review evidence; `render-final-coverage.mjs` renders coverage; `validate-final.mjs` runs current regressions, TypeScript and accepted-candidate checks without synthesis. Provider review preparation requires the ignored downloaded hash-verified artifact; portable tests use its retained sanitized evidence. Website build and secret/link scans are recorded separately.

The initial `prepare-design.mjs`, four-resource template, migration-role proposal and snapshot-only `transform.mjs.reverse` remain historical Mode B preparation. Do not substitute them for the final two-resource Mode A proposal. `nativeToLegacy` supports newly created target records without a source snapshot; Coach-private notes are explicitly non-reversible and disabled during the rollback window. No live restore/import or runtime fence is implied.

Read [migration control](../../docs/architecture/README-PHASE2-MIGRATION.md) and the [M4 migration plan](../../docs/architecture/team-hub-2b3-migration-plan.md).

Offline: `node scripts/team-hub-migration/dry-run.mjs --synthetic` or `--empty`; `node --test scripts/team-hub-migration/*.test.mjs`. `--input` accepts an access-controlled normalized four-array source artifact, reads it in memory and prints only counts/digests. Never place real source artifacts in the repository. There is no AWS writing adapter. Recovery data returned by the library is sensitive and must remain outside Git; the CLI never emits it.

`prepare-design.mjs` renders a **proposal**, preserves the accepted eleven-resource product template and adds four dark-state declarations. It does not synthesize/deploy any root. `dark-target.template.json` is not a pinned deployment assembly and has not passed an AWS change-set gate. The two-table offline application design, M4 persistence proposal and accepted synthetic runtime are distinct states; do not substitute one for another.

Read-only live tools require fresh scope authorization and the existing default profile: `verify-legacy.mjs after`, `verify-tournament.mjs`, `verify-team.mjs`, `inventory-live.mjs`, `inspect-consumers.mjs`. They write only sanitized local evidence. The inventory allows scans only after four exact Ntgre CloudFormation identities match; source logo listing is restricted to `team-logos/`. No item attributes are retrieved when both count passes are zero. Nonempty future inventories stop the live dry-run claim pending in-memory structural transformation and association reconciliation; do not infer success from counts alone.

Restart is content-addressed and deterministic over an immutable normalized source artifact. It is not a deployed scan-cursor/checkpoint service or a resumable live-copy engine. The initial `transform.mjs.reverse` supports unchanged transformed snapshots only; the current `native-state.mjs` codec separately handles native new records under the final rollback contract. Live import, replay protection and restore rehearsal remain later gates. Fence tests exercise a protocol model, not an installed server-side fence. Use `update-final-control.mjs` for current preparation status; the initial `update-control.mjs` records the historical blocked stage.
